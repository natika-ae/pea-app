# ระบบศูนย์อบรมออนไลน์ PEA — Requirement, กติกาธุรกิจ และ User Story

Oct 27, 2026 · @Akenarin Komkoon

## 0. ขอบเขตและสมมติฐาน

ระบบนี้คือเว็บรวมหลักสูตรอบรมออนไลน์ผ่านวิดีโอของศูนย์อบรม กฟภ. ผู้ใช้สมัครสมาชิก ขอลงทะเบียนหลักสูตร รอผู้ดูแลอนุมัติ เรียนวิดีโอจนครบ ทำแบบทดสอบหลังเรียน แล้วได้ใบประกาศนียบัตรที่ตรวจสอบได้

**ผู้ใช้งาน (Actor)**

| Actor | คำอธิบาย |
| --- | --- |
| ผู้เยี่ยมชม (Guest) | ยังไม่ login ดูรายการหลักสูตร รายละเอียด และบทเรียนตัวอย่างได้ |
| ผู้เรียน (Learner) | สมาชิกที่ login แล้ว แบ่งเป็น `EMPLOYEE` (พนักงาน กฟภ.) และ `PUBLIC` (บุคคลภายนอก) |
| ผู้ดูแลระบบ (Admin) | เจ้าหน้าที่ศูนย์อบรม จัดการหลักสูตร อนุมัติการลงทะเบียน และดู dashboard |
| ผู้ตรวจสอบใบประกาศ | บุคคลภายนอก เช่น ฝ่ายบุคคลของหน่วยงานอื่น เปิดลิงก์ตรวจสอบใบประกาศโดยไม่ต้อง login |

**สมมติฐานที่ใช้ในเอกสาร** (ค่าคงที่ทั้งหมดเป็นตัวอย่าง ปรับตามนโยบายจริงของศูนย์ได้)

- เวลาทั้งหมดตีความใน timezone `Asia/Bangkok` (UTC+7) และวันที่บนใบประกาศใช้ปี พ.ศ.
- ไม่มีการชำระเงิน ทุกหลักสูตรไม่มีค่าใช้จ่าย การคัดกรองผู้เรียนทำผ่านการอนุมัติของ admin
- วิดีโอฝังจากแหล่งภายนอก (เช่น YouTube unlisted หรือ video server ภายใน) ระบบรับเพียงเหตุการณ์ความคืบหน้าการดูจาก player
- รหัสพนักงาน กฟภ. สมมติว่าเป็นตัวเลข 6 หลัก (ต้องยืนยันรูปแบบจริงกับฝ่ายทรัพยากรบุคคล)
- ระดับการทดสอบใช้นิยามเดิม: Unit = pure function / schema / service ที่ inject fake repository, Integration = service + DB ทดสอบ, E2E = browser จริงผ่าน `data-testid`

## 1. Requirement ภาพรวม

ระบบมี 10 requirement ครอบคลุมเส้นทางหลัก สมัคร → ค้นหา → ลงทะเบียน → อนุมัติ → เรียน → สอบ → รับใบประกาศ

| ID | Requirement | ผู้ใช้หลัก |
| --- | --- | --- |
| R1 | ผู้ใช้สมัครสมาชิก (พนักงาน กฟภ. หรือบุคคลภายนอก) และเข้าสู่ระบบด้วยอีเมล + รหัสผ่าน | Guest, Learner |
| R2 | ผู้เยี่ยมชมดูหน้ารวมหลักสูตร ค้นหา กรองตามหมวดและประเภทผู้เรียน และเรียงลำดับได้ | Guest |
| R3 | ผู้เยี่ยมชมดูรายละเอียดหลักสูตร รายการบทเรียน และบทเรียนตัวอย่างได้ พร้อมเห็นสถานะปุ่มลงทะเบียน | Guest, Learner |
| R4 | ผู้เรียนส่งคำขอลงทะเบียนหลักสูตรได้ภายในเงื่อนไขที่กำหนด และยกเลิกคำขอที่ยังรออนุมัติได้ | Learner |
| R5 | ผู้ดูแลระบบอนุมัติหรือปฏิเสธคำขอลงทะเบียนผ่าน dashboard ได้ทีละรายการหรือหลายรายการ | Admin |
| R6 | ผู้เรียนที่ได้รับอนุมัติเรียนวิดีโอ ระบบบันทึกความคืบหน้าและตำแหน่งที่ดูค้างไว้ | Learner |
| R7 | ผู้เรียนที่เรียนครบทุกบททำแบบทดสอบหลังเรียนได้ตามจำนวนครั้งที่กำหนด | Learner |
| R8 | ระบบออกใบประกาศนียบัตรเมื่อเรียนจบตามเกณฑ์ และบุคคลภายนอกตรวจสอบความถูกต้องได้ | Learner, ผู้ตรวจสอบ |
| R9 | ผู้เรียนดูหน้า "หลักสูตรของฉัน" เห็นสถานะการลงทะเบียน ความคืบหน้า และใบประกาศของตนเอง | Learner |
| R10 | ผู้ดูแลระบบจัดการหลักสูตร/บทเรียน/แบบทดสอบ และดูสถิติบน dashboard ผู้ใช้ทั่วไปเข้าไม่ได้ | Admin |

## 2. กติกาธุรกิจ (Business Rules)

กติกาทุกข้อมีรหัส `BR-xx` เพื่ออ้างอิงจาก acceptance criteria และ test case ส่วนค่าตัวเลขรวมไว้เป็นค่าคงที่ที่เดียว

**ค่าคงที่ของระบบ**

| ค่าคงที่ | ค่า | ใช้กับ |
| --- | --- | --- |
| `MIN_PASSWORD_LENGTH` | 8 ตัวอักษร | BR-03 |
| `MAX_LOGIN_FAILURES` / `LOCKOUT_MINUTES` | 5 ครั้ง / 15 นาที | BR-06 |
| `SEARCH_MAX_LENGTH` | 100 ตัวอักษร | BR-09 |
| `PAGE_SIZE` | 12 หลักสูตรต่อหน้า | BR-12 |
| `MAX_PENDING_REQUESTS` | 5 คำขอที่รออนุมัติพร้อมกันต่อผู้ใช้ | BR-23 |
| `REJECT_REASON_LENGTH` | 10–500 ตัวอักษร | BR-28 |
| `BULK_APPROVE_MAX` | 50 รายการต่อครั้ง | BR-29 |
| `LEARNING_PERIOD_DAYS` | 60 วันนับจากวันที่อนุมัติ | BR-27, BR-39 |
| `LESSON_COMPLETE_WATCH_PERCENT` | 90% ของความยาววิดีโอ | BR-35 |
| `DEFAULT_PASSING_SCORE_PERCENT` | 70% (กำหนดรายหลักสูตรได้ 50–100) | BR-41 |
| `MAX_QUIZ_ATTEMPTS` | 3 ครั้ง | BR-42 |
| `DEFAULT_QUIZ_TIME_LIMIT_MINUTES` | 30 นาที | BR-44 |
| `EXPIRY_WARNING_DAYS` | 7 วัน | BR-51 |
| `MAX_CERTIFICATE_CODE_ATTEMPTS` | 3 ครั้ง | BR-47 |

### R4 การลงทะเบียน

ระบบตรวจตามลำดับ BR-18 → BR-24 และรายงานเหตุผลแรกที่ไม่ผ่านเพียงข้อเดียว

| BR | กติกา | Error code |
| --- | --- | --- |
| BR-18 | ต้อง login ก่อน | `UNAUTHENTICATED` |
| BR-19 | อยู่ในช่วงรับสมัคร `openAt ≤ now ≤ closeAt` โดย `closeAt` คือ 23:59:59.999 ของวันปิดรับสมัคร เวลาไทย (นับรวมขอบทั้งสองด้าน) | `REGISTRATION_NOT_OPEN` / `REGISTRATION_CLOSED` |
| BR-20 | หลักสูตร `EMPLOYEE_ONLY` รับเฉพาะผู้ใช้ประเภท `EMPLOYEE` | `EMPLOYEE_ONLY_COURSE` |
| BR-21 | ถ้ามีหลักสูตรที่ต้องผ่านก่อน ผู้ใช้ต้องมีการลงทะเบียนหลักสูตรนั้นที่สถานะ `COMPLETED` | `PREREQUISITE_NOT_MET` |
| BR-22 | ผู้ใช้ต้องไม่มีการลงทะเบียนหลักสูตรนี้ที่สถานะ `PENDING`, `APPROVED` หรือ `COMPLETED` อยู่แล้ว ส่วน `REJECTED`, `CANCELLED`, `EXPIRED`, `FAILED` ส่งคำขอใหม่ได้ (สร้างแถวใหม่ เก็บประวัติเดิมไว้) | `ALREADY_REGISTERED` |
| BR-23 | ผู้ใช้มีคำขอ `PENDING` รวมทุกหลักสูตรได้ไม่เกิน 5 รายการ | `TOO_MANY_PENDING` |
| BR-24 | ที่นั่งคงเหลือต้องมากกว่า 0 (ไม่ตรวจถ้า `capacity = null`) | `COURSE_FULL` |
| BR-25 | ผู้ใช้ยกเลิกคำขอได้เฉพาะของตนเองที่สถานะ `PENDING` เท่านั้น | `CANNOT_CANCEL` |
| BR-26 | กดลงทะเบียนซ้ำหรือเปิดสองแท็บพร้อมกัน ต้องได้คำขอเพียง 1 รายการ (guard ด้วย unique constraint ของการลงทะเบียนที่ยัง active) | `ALREADY_REGISTERED` |

### R5 การอนุมัติโดยผู้ดูแลระบบ

| BR | กติกา | Error code |
| --- | --- | --- |
| BR-27 | อนุมัติได้เฉพาะคำขอ `PENDING` และต้องตรวจที่นั่งใหม่ ณ เวลาอนุมัติ เมื่ออนุมัติแล้วบันทึก `approvedAt = now` และ `expiresAt = approvedAt + 60 วัน` | `NOT_PENDING` / `COURSE_FULL` |
| BR-28 | ปฏิเสธได้เฉพาะคำขอ `PENDING` และต้องระบุเหตุผลยาว 10–500 ตัวอักษร ผู้เรียนเห็นเหตุผลนี้ | `NOT_PENDING` / `VALIDATION_FAILED` |
| BR-29 | อนุมัติหลายรายการได้ครั้งละไม่เกิน 50 รายการ ถ้าที่นั่งไม่พอให้อนุมัติตามลำดับเวลาที่ส่งคำขอ (มาก่อนได้ก่อน) ส่วนที่เหลือคง `PENDING` และรายงานผลรายรายการ | `BULK_LIMIT_EXCEEDED` |
| BR-30 | ทุกการอนุมัติ/ปฏิเสธบันทึกผู้ดำเนินการและเวลา (audit) และส่งอีเมลแจ้งผู้เรียน การส่งอีเมลล้มเหลวไม่ทำให้การอนุมัติถูกยกเลิก | – |
| BR-31 | admin สองคนอนุมัติคำขอเดียวกันพร้อมกัน ต้องสำเร็จครั้งเดียว (guard อยู่ในคำสั่งเขียน `where status = PENDING`) และการอนุมัติพร้อมกันต้องไม่ทำให้เกิน `capacity` | `NOT_PENDING` |
| BR-32 | คิวรออนุมัติเรียงตามเวลาที่ส่งคำขอเก่าสุดก่อน กรองตามหลักสูตรได้ และแสดงจำนวนวันที่รอ | – |

### R6 การเรียนวิดีโอ

| BR | กติกา | Error code |
| --- | --- | --- |
| BR-33 | บท preview ดูได้ทุกคน บทอื่นต้องมีการลงทะเบียน `APPROVED` ที่ `now ≤ expiresAt` หรือ `COMPLETED` (ดูทบทวนได้ไม่มีวันหมดอายุ) | `NOT_APPROVED` / `ENROLLMENT_EXPIRED` |
| BR-34 | ถ้าหลักสูตรตั้ง `sequential = true` บทที่ n เปิดได้เมื่อบทที่ n−1 เรียนจบแล้ว | `LESSON_LOCKED` |
| BR-35 | บทเรียนถือว่าจบเมื่อเวลาที่ดูจริงแบบไม่นับช่วงซ้ำ ≥ 90% ของความยาววิดีโอ การลากข้ามไม่นับเป็นเวลาที่ดู | – |
| BR-36 | บันทึกตำแหน่งล่าสุดทุก 10 วินาทีและเมื่อกดหยุด เปิดบทเดิมอีกครั้งเล่นต่อจากตำแหน่งนั้น | – |
| BR-37 | ความคืบหน้า = `floor(บทที่จบ / บททั้งหมด × 100)` ถ้าไม่มีบทได้ 0 ไม่เกิน 100 และการจบบทเดิมซ้ำไม่เพิ่มค่า | – |
| BR-38 | ถ้าเพิ่มบทเรียนใหม่หลังผู้เรียนเริ่มเรียน ความคืบหน้าของผู้ที่ยัง `APPROVED` คำนวณใหม่ตามจำนวนบทปัจจุบัน ส่วนผู้ที่ `COMPLETED` แล้วไม่ได้รับผลกระทบ | – |
| BR-39 | เมื่อเลย `expiresAt` โดยยังไม่ `COMPLETED` สถานะเป็น `EXPIRED` เข้าเรียนต่อไม่ได้ แต่ส่งคำขอใหม่ได้ (ความคืบหน้าเริ่มใหม่) | `ENROLLMENT_EXPIRED` |

| BR-44 | จำกัดเวลาตามหลักสูตร (ค่าเริ่มต้น 30 นาที) ส่งหลัง `startedAt + เวลาที่กำหนด` ถือเป็นการทำ 1 ครั้งที่ได้ 0 คะแนน | `QUIZ_TIME_EXCEEDED` |

## 3. State Transition ของการลงทะเบียน

การลงทะเบียนเริ่มที่ `PENDING` และจบได้ 5 แบบ มีเพียง `COMPLETED` ที่ได้ใบประกาศ ส่วนอีก 4 แบบส่งคำขอใหม่ได้

&#91;embedded content: สถานะการลงทะเบียน · 7 สถานะ\]

เฉพาะ `APPROVED` และ `COMPLETED` นับเป็นที่นั่ง การเปลี่ยนสถานะที่ไม่อยู่ในแผนภาพต้องถูกปฏิเสธ เช่น อนุมัติคำขอที่ `REJECTED` แล้ว หรือยกเลิกคำขอที่ `APPROVED` แล้ว

## 4. User Story และ Acceptance Criteria

มี 17 user story ครอบคลุม R1–R10 แต่ละ AC อ้างกติกาธุรกิจที่เกี่ยวข้องในวงเล็บ

### US-01 สมัครสมาชิก (R1)

> **ในฐานะ** ผู้เยี่ยมชม **ฉันต้องการ** สมัครสมาชิกโดยระบุว่าเป็นพนักงาน กฟภ. หรือบุคคลภายนอก **เพื่อ** ลงทะเบียนหลักสูตรที่เปิดให้กลุ่มของฉัน

- AC1 กรอกชื่อ-นามสกุล 2–100 ตัวอักษร อีเมลถูกรูปแบบ และรหัสผ่าน ≥ 8 ตัวที่ยืนยันตรงกัน จึงสมัครได้ (BR-01, BR-03)
- AC2 อีเมลที่มีในระบบแล้ว แม้ต่างตัวพิมพ์หรือมีช่องว่างหน้า-หลัง แสดง "อีเมลนี้ถูกใช้แล้ว" (BR-02)
- AC3 เลือก "พนักงาน กฟภ." แล้ว ช่องรหัสพนักงานและสังกัดเป็นช่องบังคับ รหัสต้องเป็นตัวเลข 6 หลักที่ไม่ซ้ำ (BR-04)
- AC4 เลือก "พนักงาน กฟภ." แต่ใช้อีเมลนอกโดเมน `@pea.co.th` แสดง "พนักงานต้องใช้อีเมล @pea.co.th" (BR-05)
- AC5 เลือก "บุคคลภายนอก" ช่องรหัสพนักงานถูกซ่อน และไม่บันทึกค่าแม้ส่งมาจาก client (BR-04)
- AC6 กรอกผิดแล้วข้อมูลที่กรอกไว้ยังอยู่ ยกเว้นช่องรหัสผ่าน

### US-02 เข้าสู่ระบบ (R1)

> **ในฐานะ** สมาชิก **ฉันต้องการ** เข้าสู่ระบบแล้วกลับไปหน้าที่ฉันเปิดค้างไว้ **เพื่อ** ทำต่อได้ทันที

- AC1 อีเมลหรือรหัสผ่านผิดแสดงข้อความเดียวกัน "อีเมลหรือรหัสผ่านไม่ถูกต้อง" (ไม่บอกว่าผิดช่องไหน)
- AC2 ผิดติดต่อกันครบ 5 ครั้ง บัญชีถูกล็อก 15 นาที ระหว่างล็อกแม้รหัสถูกก็เข้าไม่ได้ (BR-06)
- AC3 เข้าสำเร็จแล้วตัวนับครั้งที่ผิดกลับเป็น 0 (BR-06)
- AC4 เข้าสำเร็จแล้วกลับไปตาม `?next=` เฉพาะ path ภายใน เช่น `/courses/SAF-101` ส่วน URL ภายนอกหรือ `//host` กลับหน้า `/` (BR-07)

### US-03 ค้นหาหลักสูตร (R2)

> **ในฐานะ** ผู้เยี่ยมชม **ฉันต้องการ** ค้นหาหลักสูตรจากชื่อหรือรหัส กรองตามหมวด และเรียงลำดับ **เพื่อ** หาหลักสูตรที่ตรงกับงานของฉัน

- AC1 หน้า `/courses` แสดงการ์ดหลักสูตรที่เผยแพร่แล้วหน้าละ 12 รายการ แต่ละการ์ดมีรหัส ชื่อ หมวด ชั่วโมงอบรม ป้าย "เฉพาะพนักงาน" (ถ้ามี) และสถานะรับสมัคร (BR-08, BR-12)
- AC2 ค้นหา `saf` หรือ `ความปลอดภัย` พบหลักสูตร `SAF-101` ไม่สนตัวพิมพ์ และช่องว่างหน้า-หลังไม่มีผล (BR-09)
- AC3 กรองหมวดและกลุ่มผู้เรียนพร้อมกันได้ ค่าที่ไม่รู้จักใน URL ไม่ทำให้หน้า error (BR-10)
- AC4 เรียง `closing-soon` แสดงเฉพาะหลักสูตรที่ยังเปิดรับ โดยวันปิดใกล้สุดขึ้นก่อน (BR-11)
- AC5 ค่าค้นหา กรอง เรียง และหน้า อยู่ใน URL เปิดลิงก์เดิมได้ผลเหมือนเดิม
- AC6 ไม่พบผลลัพธ์แสดง "ไม่พบหลักสูตรที่ตรงกับการค้นหา" พร้อมปุ่มล้างตัวกรอง

### US-04 ดูรายละเอียดหลักสูตร (R3)

> **ในฐานะ** ผู้เยี่ยมชม **ฉันต้องการ** ดูรายละเอียด รายการบทเรียน และลองดูบทตัวอย่าง **เพื่อ** ตัดสินใจก่อนลงทะเบียน

- AC1 หน้า `/courses/{code}` แสดงข้อมูลตาม BR-13 และชั่วโมงอบรมแสดงเป็น "3 ชม. 25 นาที"
- AC2 รายการบทเรียนแสดงชื่อและความยาวทุกบท บท preview มีปุ่ม "ดูตัวอย่าง" ที่ดูได้โดยไม่ login (BR-14)
- AC3 ที่นั่งคงเหลือคำนวณตาม BR-16 เช่น capacity 40 อนุมัติแล้ว 38 จบแล้ว 2 แสดง "เต็ม"
- AC4 ปุ่มลงทะเบียนแสดงสถานะเดียวตามตารางด้านล่าง ตรวจจากบนลงล่างและหยุดที่แถวแรกที่เป็นจริง (BR-15)

| ลำดับ | เงื่อนไข | ปุ่ม/ข้อความ | กดได้ |
| --- | --- | --- | --- |
| 1 | ยังไม่ login | เข้าสู่ระบบเพื่อลงทะเบียน | ได้ (ไปหน้า login พร้อม `?next=`) |
| 2 | มีการลงทะเบียน `COMPLETED` | ดูใบประกาศนียบัตร | ได้ |

| 5 | หลักสูตร `EMPLOYEE_ONLY` และผู้ใช้เป็น `PUBLIC` | เฉพาะพนักงาน กฟภ. | ไม่ได้ |
| 6 | ยังไม่ถึง `openAt` | เปิดรับสมัคร 1 พฤศจิกายน 2569 | ไม่ได้ |

### US-05 ส่งคำขอลงทะเบียน (R4)

> **ในฐานะ** ผู้เรียน **ฉันต้องการ** กดลงทะเบียนหลักสูตร **เพื่อ** ส่งคำขอให้ศูนย์อบรมพิจารณา

- AC1 คำขอที่ผ่านทุกเงื่อนไขได้สถานะ `PENDING` พร้อม `requestedAt = now` และหน้าจอแสดง "ส่งคำขอแล้ว รอการอนุมัติ" (BR-18–BR-24)
- AC2 ไม่ผ่านเงื่อนไขใด ระบบไม่สร้างคำขอ และแสดงเหตุผลแรกตามลำดับ login → ช่วงรับสมัคร → กลุ่มผู้เรียน → หลักสูตรที่ต้องผ่านก่อน → ลงทะเบียนซ้ำ → จำนวนคำขอค้าง → ที่นั่ง
- AC3 กดลงทะเบียนเวลา 23:59:59 ของวันปิดรับสมัครยังส่งได้ แต่ 00:00:00 ของวันถัดไปไม่ได้ (BR-19)
- AC4 ผู้ใช้ที่เคยถูกปฏิเสธ ยกเลิก หมดอายุ หรือสอบไม่ผ่าน ส่งคำขอใหม่ได้ และประวัติเดิมยังอยู่ (BR-22)
- AC5 ผู้ใช้ที่มีคำขอค้าง 5 รายการ ส่งคำขอที่ 6 ไม่ได้ (BR-23)
- AC6 กดปุ่มซ้ำเร็ว ๆ หรือส่งจากสองแท็บพร้อมกันได้คำขอ 1 รายการ (BR-26)

### US-06 ยกเลิกคำขอลงทะเบียน (R4)

> **ในฐานะ** ผู้เรียน **ฉันต้องการ** ยกเลิกคำขอที่ยังรออนุมัติ **เพื่อ** คืนโควตาคำขอค้างให้ตัวเอง

- AC1 ยกเลิกคำขอ `PENDING` ของตนเองได้ สถานะเป็น `CANCELLED` และจำนวนคำขอค้างลดลง 1 (BR-25)
- AC2 คำขอที่อนุมัติหรือปฏิเสธไปแล้วยกเลิกไม่ได้ (BR-25)
- AC3 ยกเลิกคำขอของผู้ใช้อื่นไม่ได้ และตอบเหมือนไม่พบรายการ (ไม่เปิดเผยว่ามีอยู่)

### US-07 อนุมัติหรือปฏิเสธคำขอ (R5)

> **ในฐานะ** เจ้าหน้าที่ศูนย์อบรม **ฉันต้องการ** ดูคิวคำขอและอนุมัติหรือปฏิเสธพร้อมเหตุผล **เพื่อ** คัดผู้เรียนให้ตรงกลุ่มเป้าหมายและจำนวนที่นั่ง

- AC1 หน้า `/admin/enrollments` แสดงคำขอ `PENDING` เรียงเก่าสุดก่อน มีชื่อ ประเภท สังกัด รหัสพนักงาน หลักสูตร และจำนวนวันที่รอ กรองตามหลักสูตรได้ (BR-32)
- AC2 อนุมัติแล้วสถานะเป็น `APPROVED` มี `approvedAt` และ `expiresAt = approvedAt + 60 วัน` ผู้เรียนได้อีเมลแจ้ง (BR-27, BR-30)
- AC3 อนุมัติเมื่อที่นั่งเต็มแล้วไม่สำเร็จ แสดง "หลักสูตรนี้เต็มแล้ว" และคำขอยัง `PENDING` (BR-27)
- AC4 ปฏิเสธต้องกรอกเหตุผล 10–500 ตัวอักษร ผู้เรียนเห็นเหตุผลในหน้าหลักสูตรของฉันและในอีเมล (BR-28)
- AC5 admin สองคนกดอนุมัติคำขอเดียวกันพร้อมกัน สำเร็จ 1 คน อีกคนเห็น "คำขอนี้ถูกดำเนินการไปแล้ว" (BR-31)
- AC6 ส่งอีเมลไม่สำเร็จ สถานะยังเป็น `APPROVED` และระบบบันทึก log ไว้ส่งใหม่ (BR-30)

### US-08 อนุมัติหลายรายการพร้อมกัน (R5)

> **ในฐานะ** เจ้าหน้าที่ศูนย์อบรม **ฉันต้องการ** เลือกหลายคำขอแล้วอนุมัติครั้งเดียว **เพื่อ** ประหยัดเวลาช่วงเปิดรับสมัคร

- AC1 เลือกได้ไม่เกิน 50 รายการต่อครั้ง (BR-29)
- AC2 ที่นั่งเหลือ 3 แต่เลือก 5 คำขอ ระบบอนุมัติ 3 รายการที่ส่งคำขอก่อน และอีก 2 รายการยัง `PENDING` (BR-29)
- AC3 หลังกดแสดงสรุปผลรายรายการ เช่น "อนุมัติ 3 · ที่นั่งเต็ม 2" และรายการที่ถูกดำเนินการไปแล้วโดยคนอื่นแสดง "ข้าม"

### US-09 เรียนวิดีโอและบันทึกความคืบหน้า (R6)

> **ในฐานะ** ผู้เรียนที่ได้รับอนุมัติ **ฉันต้องการ** ดูวิดีโอทีละบท เล่นต่อจากที่ค้างไว้ และเห็นเปอร์เซ็นต์ความคืบหน้า **เพื่อ** เรียนให้จบภายในเวลาที่กำหนด

- AC1 เข้าบทที่ไม่ใช่ preview ได้เมื่อการลงทะเบียน `APPROVED` และยังไม่หมดอายุ หรือ `COMPLETED` แล้ว (BR-33)
- AC2 หลักสูตรที่บังคับเรียนตามลำดับ บทถัดไปแสดงไอคอนล็อกจนกว่าบทก่อนหน้าจะจบ (BR-34)
- AC3 ดูวิดีโอ 10 นาทีครบ 9 นาที (90%) บทนั้นถูกทำเครื่องหมายจบอัตโนมัติ ลากไปท้ายวิดีโอโดยไม่ได้ดูไม่นับ (BR-35)
- AC4 ปิดหน้าแล้วกลับมาเปิดบทเดิม วิดีโอเล่นต่อจากตำแหน่งที่บันทึกล่าสุด คลาดเคลื่อนไม่เกิน 10 วินาที (BR-36)
- AC5 ความคืบหน้าเป็นจำนวนเต็ม เช่น จบ 2 จาก 3 บทแสดง 66% และดูบทที่จบแล้วซ้ำไม่เพิ่มค่า (BR-37)
- AC6 หลักสูตรเพิ่มบทใหม่ ผู้ที่กำลังเรียนเห็นความคืบหน้าลดลงตามจำนวนบทใหม่ ผู้ที่จบแล้วยังเป็น 100% (BR-38)

### US-10 ระยะเวลาเรียนหมดอายุ (R6)

> **ในฐานะ** ศูนย์อบรม **ฉันต้องการ** ให้สิทธิ์เรียนหมดอายุหลังอนุมัติ 60 วัน **เพื่อ** คืนที่นั่งให้ผู้ที่ตั้งใจเรียน

- AC1 อนุมัติวันที่ 1 ตุลาคม 2569 เวลา 10:00 เรียนได้ถึง 30 พฤศจิกายน 2569 เวลา 10:00 (BR-27, BR-33)
- AC2 เลย `expiresAt` โดยยังไม่จบ สถานะเป็น `EXPIRED` เปิดบทเรียนเห็น "สิทธิ์เรียนหมดอายุแล้ว" พร้อมปุ่มลงทะเบียนใหม่ (BR-39)
- AC3 การลงทะเบียนที่ `EXPIRED` ไม่นับเป็นที่นั่ง จึงคืนที่นั่งให้คำขออื่น (BR-16)

### US-11 ทำแบบทดสอบหลังเรียน (R7)

> **ในฐานะ** ผู้เรียน **ฉันต้องการ** ทำแบบทดสอบหลังเรียนครบทุกบท **เพื่อ** แสดงว่าเข้าใจเนื้อหาและได้รับใบประกาศ

- AC1 ปุ่ม "ทำแบบทดสอบ" กดได้เมื่อความคืบหน้า 100% เท่านั้น (BR-40)
- AC2 แบบทดสอบ 20 ข้อ ตอบถูก 14 ข้อได้ 70% ผ่านเกณฑ์ 70 ส่วนถูก 13 ข้อได้ 65% ไม่ผ่าน (BR-41)
- AC3 หน้าจอแสดงจำนวนครั้งที่เหลือ ไม่ผ่านครบ 3 ครั้ง สถานะเป็น `FAILED` และแสดงปุ่มลงทะเบียนใหม่ (BR-42)
- AC4 ยังตอบไม่ครบทุกข้อ ปุ่มส่งกดไม่ได้ และ server ปฏิเสธถ้าส่งมาไม่ครบ (BR-43)
- AC5 นาฬิกานับถอยหลังแสดงเวลาที่เหลือ ส่งหลังหมดเวลานับเป็น 1 ครั้งที่ได้ 0 คะแนน (BR-44)
- AC6 หลังส่งแสดงคะแนนและผลผ่าน/ไม่ผ่าน แต่ไม่แสดงเฉลยรายข้อ (BR-43)

### US-12 รับใบประกาศนียบัตร (R8)

> **ในฐานะ** ผู้เรียน **ฉันต้องการ** ได้ใบประกาศทันทีที่เรียนจบตามเกณฑ์ **เพื่อ** ใช้เป็นหลักฐานชั่วโมงอบรม

- AC1 สอบผ่าน (หรือจบบทสุดท้ายในหลักสูตรที่ไม่มีแบบทดสอบ) แล้วสถานะเป็น `COMPLETED` และมีใบประกาศ 1 ใบ (BR-45, BR-46)
- AC2 รหัสใบประกาศของผู้ที่จบวันที่ 27 ตุลาคม 2569 ขึ้นต้น `PEA-TC-2569-` และผู้ที่จบ 1 มกราคม 2570 เวลา 00:30 น. เวลาไทยได้ `PEA-TC-2570-` (BR-47)
- AC3 ใบประกาศแสดงชื่อ หลักสูตร ชั่วโมงอบรม วันที่จบแบบไทย และ QR code แก้ชื่อในโปรไฟล์ภายหลังไม่เปลี่ยนชื่อบนใบเดิม (BR-48)
- AC4 ดาวน์โหลด PDF ได้จากหน้าหลักสูตรของฉัน ผู้ใช้อื่นเปิดลิงก์ดาวน์โหลดได้ 403 (BR-50)

### US-13 ตรวจสอบใบประกาศ (R8)

> **ในฐานะ** ผู้ตรวจสอบจากหน่วยงานภายนอก **ฉันต้องการ** สแกน QR หรือกรอกรหัสใบประกาศ **เพื่อ** ยืนยันว่าเป็นใบจริงที่ออกโดยศูนย์อบรม กฟภ.

- AC1 เปิด `/verify/{code}` โดยไม่ login เห็นชื่อผู้เรียน หลักสูตร ชั่วโมงอบรม และวันที่จบ (BR-49)
- AC2 รหัสที่ไม่มีอยู่หรือรูปแบบผิดแสดงหน้า 404 "ไม่พบใบประกาศนียบัตรนี้" ไม่ใช่ 500 (BR-49)
- AC3 ใบที่ถูกเพิกถอนแสดง "ใบประกาศนี้ถูกเพิกถอนแล้ว" พร้อมวันที่เพิกถอน (BR-49)
- AC4 หน้าตรวจสอบไม่แสดงอีเมล รหัสพนักงาน หรือข้อมูลติดต่อของผู้เรียน

### US-14 หลักสูตรของฉัน (R9)

> **ในฐานะ** ผู้เรียน **ฉันต้องการ** เห็นทุกหลักสูตรที่ฉันลงทะเบียนพร้อมสถานะ **เพื่อ** รู้ว่าต้องทำอะไรต่อ

- AC1 หน้า `/my-courses` แยกแท็บ รออนุมัติ / กำลังเรียน / จบแล้ว / ไม่สำเร็จ (ปฏิเสธ ยกเลิก หมดอายุ สอบไม่ผ่าน) (BR-51)
- AC2 แท็บกำลังเรียนแสดงความคืบหน้าและ "เหลือ 12 วัน" เหลือ ≤ 7 วันแสดงเป็นสีเตือน วันสุดท้ายแสดง "วันสุดท้าย" (BR-51, BR-52)
- AC3 คำขอที่ถูกปฏิเสธแสดงเหตุผลจาก admin (BR-53)
- AC4 ผู้ใช้เห็นเฉพาะข้อมูลของตนเอง (BR-53)

### US-15 จัดการหลักสูตร บทเรียน และแบบทดสอบ (R10)

> **ในฐานะ** เจ้าหน้าที่ศูนย์อบรม **ฉันต้องการ** สร้างและแก้ไขหลักสูตร บทเรียนวิดีโอ และข้อสอบ **เพื่อ** เปิดหลักสูตรใหม่ได้เอง

- AC1 สร้างหลักสูตรด้วยรหัสรูปแบบ `SAF-101` ที่ไม่ซ้ำ รหัสผิดรูปแบบหรือซ้ำแสดงข้อความที่ช่องรหัส (BR-55)
- AC2 วันปิดรับสมัครก่อนวันเปิดบันทึกไม่ได้ (BR-55)
- AC3 ช่องจำนวนที่นั่งเว้นว่างคือไม่จำกัด กรอก 0 หรือมากกว่า 500 ไม่ผ่าน และลดจำนวนที่นั่งต่ำกว่าผู้ที่อนุมัติแล้วไม่ได้ (BR-56)
- AC4 หลักสูตรที่มีการลงทะเบียนแล้วไม่มีปุ่มลบ มีแต่ "ยกเลิกการเผยแพร่" (BR-57)
- AC5 ลำดับบทเรียนซ้ำในหลักสูตรเดียวกันบันทึกไม่ได้ (BR-58)
- AC6 กรอกผิดแล้วข้อมูลในฟอร์มไม่หาย

### US-16 Dashboard สถิติ (R10)

> **ในฐานะ** ผู้อำนวยการศูนย์อบรม **ฉันต้องการ** ดูจำนวนคำขอ ผู้เรียน และผู้จบย้อนหลัง **เพื่อ** วางแผนเปิดรุ่นและติดตามผลการอบรม

- AC1 การ์ดสรุปแสดง คำขอรออนุมัติ ผู้กำลังเรียน ผู้จบในช่วงที่เลือก อัตราการจบ และวันรออนุมัติเฉลี่ย (BR-59)
- AC2 เลือกช่วง 7 / 30 / 90 วัน ค่าเริ่มต้น 30 วัน ค่าอื่นใน URL ใช้ 30 วัน (BR-59)
- AC3 กราฟผู้จบรายวันมีจุดครบทุกวันรวมวันนี้ วันที่ไม่มีผู้จบเป็น 0 และจัดวันตามเวลาไทย (BR-60)
- AC4 ยังไม่มีผู้จบหรือหมดอายุเลย อัตราการจบแสดง 0% ไม่ใช่ error (BR-59)

### US-17 สิทธิ์ผู้ดูแลระบบ (R10)

> **ในฐานะ** ศูนย์อบรม **ฉันต้องการ** ให้เฉพาะเจ้าหน้าที่เข้าหน้า admin ได้ **เพื่อ** ปกป้องข้อมูลส่วนบุคคลของผู้เรียน

- AC1 ไม่ login เปิด `/admin` ไปหน้า `/login?next=/admin` และเรียก `/api/admin/*` ได้ 401 (BR-54)
- AC2 ผู้เรียนเปิด `/admin` ไปหน้า `/` และเรียก API ได้ 403 (BR-54)
- AC3 role ต้องเป็น `ADMIN` ตรงตัว ค่า `admin` หรือ `Admin` ไม่ถือเป็นผู้ดูแล (BR-54)
