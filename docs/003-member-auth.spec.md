# Spec 003 — สมัครสมาชิกและเข้าสู่ระบบ (R1)

| รายการ | ค่า |
|---|---|
| สถานะ | Draft — รูปแบบรหัสพนักงานและรายชื่อสังกัดรอยืนยันจากศูนย์อบรม |
| อ้างอิง | R1, US-01, US-02, BR-01 – BR-07 ใน `system_ requirement.md.md` |
| ผู้ใช้ | ผู้เยี่ยมชม (Guest), ผู้เรียน (Learner) ประเภท `EMPLOYEE` และ `PUBLIC` |

> เอกสารนี้บอกว่า **ระบบสมาชิกต้องทำอะไรและเพราะอะไร** ไม่ระบุเทคโนโลยีหรือโครงสร้างโค้ด

## 1. Goal

ผู้เยี่ยมชมสมัครสมาชิกได้เองในครั้งเดียว โดยระบุว่าเป็นพนักงาน กฟภ. หรือบุคคลภายนอก เพื่อให้ระบบรู้ว่ามีสิทธิ์ลงทะเบียนหลักสูตรกลุ่มไหน จากนั้นเข้าสู่ระบบด้วยอีเมลและรหัสผ่าน แล้วกลับไปทำต่อที่หน้าเดิมได้ทันที โดยบัญชีปลอดภัยจากการเดารหัสผ่าน

## 2. Scope

**อยู่ในขอบเขต:** หน้าสมัครสมาชิก `/register`, หน้าเข้าสู่ระบบ `/login`, การออกจากระบบ, การล็อกบัญชีเมื่อ login ผิดติดต่อกัน, การกลับไปหน้าเดิมตาม `?next=`, ลิงก์ "เข้าสู่ระบบ" / "สมัครสมาชิก" / "ออกจากระบบ" ในเมนูหลัก

**อยู่นอกขอบเขต:** ลืมรหัสผ่าน / รีเซ็ตรหัสผ่าน, ยืนยันอีเมลก่อนใช้งาน, แก้ไขโปรไฟล์, เข้าสู่ระบบผ่าน Google / SSO ของ กฟภ., ตรวจรหัสพนักงานกับระบบ HR, CAPTCHA, admin สร้างหรือปลดล็อกบัญชีให้ผู้ใช้, การกำหนด role `ADMIN` (อยู่ใน R10)

## 5. Acceptance Scenarios

### 5.1 สมัครสมาชิก (US-01)

**AS-01 สมัครบุคคลภายนอกสำเร็จ**
- Given ผู้เยี่ยมชมเปิด `/register`
- When เลือก "บุคคลภายนอก" กรอกชื่อ `สมหญิง ใจดี` อีเมล `somying@example.com` รหัสผ่าน `secret123` สองช่องตรงกัน และติ๊กยินยอม
- Then สมัครสำเร็จ อยู่ในสถานะ login และไปหน้า `/`
- And บัญชีมีประเภท `PUBLIC` role ผู้เรียน และไม่มีรหัสพนักงานหรือสังกัด

**AS-02 สมัครพนักงานสำเร็จ**
- When เลือก "พนักงาน กฟภ." กรอกอีเมล `somchai@pea.co.th` รหัสพนักงาน `123456` เลือกสังกัด และกรอกช่องอื่นถูกต้อง
- Then สมัครสำเร็จ บัญชีมีประเภท `EMPLOYEE` พร้อมรหัสพนักงานและสังกัดที่เลือก

**AS-08 บุคคลภายนอกไม่ถูกบันทึกรหัสพนักงาน** (BR-04)
- Given เลือก "พนักงาน กฟภ." กรอกรหัสพนักงาน `123456` แล้วเปลี่ยนเป็น "บุคคลภายนอก"
- Then ช่องรหัสพนักงานและสังกัดถูกซ่อน
- When ส่งคำขอสมัครประเภท `PUBLIC` ที่แนบรหัสพนักงานและสังกัดมาโดยตรง (ไม่ผ่านฟอร์ม)
- Then สมัครสำเร็จ และบัญชีไม่มีรหัสพนักงานหรือสังกัด
- And รหัส `123456` ยังใช้สมัครเป็นพนักงานได้

**AS-09 ข้อมูลในฟอร์มไม่หาย** (AU-06)
- Given กรอกทุกช่อง แต่ชื่อยาว 1 ตัวอักษรและรหัสผ่านไม่ตรงกัน
- When กด "สมัครสมาชิก"
- Then แสดงข้อผิดพลาดใต้ช่องชื่อและช่องยืนยันรหัสผ่านพร้อมกัน
- And ประเภท ชื่อ อีเมล รหัสพนักงาน สังกัด และ checkbox ยังมีค่าเดิม
- And ช่องรหัสผ่านและยืนยันรหัสผ่านถูกล้างเป็นค่าว่าง

**AS-10 ต้องให้ความยินยอม** (AU-01)
- When กรอกทุกช่องถูกต้องแต่ไม่ติ๊กยินยอม
- Then ไม่สร้างบัญชี และแสดง "กรุณายอมรับนโยบายคุ้มครองข้อมูลส่วนบุคคล"

**AS-11 สมัครพร้อมกัน** (AU-05)
- When ส่งคำขอสมัครด้วยอีเมล `new@example.com` 2 ครั้งพร้อมกัน
- Then มีบัญชี `new@example.com` 1 บัญชี และอีกคำขอได้ "อีเมลนี้ถูกใช้แล้ว"

**AS-12 ฟอร์มสมัครกำหนด role ไม่ได้** (AU-04)
- When ส่งคำขอสมัครที่แนบ role `ADMIN` มาโดยตรง
- Then บัญชีที่สร้างได้ role ผู้เรียน

### 5.2 เข้าสู่ระบบ (US-02)

**AS-13 ไม่บอกว่าผิดช่องไหน** (AU-07) Given มีบัญชี `somchai@pea.co.th` รหัสผ่าน `secret123`

| อีเมล | รหัสผ่าน | ผล |
|---|---|---|
| `somchai@pea.co.th` | `secret123` | เข้าสู่ระบบสำเร็จ |
| `  SOMCHAI@pea.co.th ` | `secret123` | เข้าสู่ระบบสำเร็จ |
| `somchai@pea.co.th` | `Secret123` | อีเมลหรือรหัสผ่านไม่ถูกต้อง |
| `nobody@pea.co.th` | `secret123` | อีเมลหรือรหัสผ่านไม่ถูกต้อง |

- And ช่องรหัสผ่านถูกล้าง ช่องอีเมลยังมีค่าเดิม

**AS-14 ล็อกบัญชี** (BR-06, AU-08)

| เวลา (ไทย) | การกระทำ | ผล |
|---|---|---|
| 10:00 – 10:04 | รหัสผิดครั้งที่ 1–4 | อีเมลหรือรหัสผ่านไม่ถูกต้อง |
| 10:05:00 | รหัสผิดครั้งที่ 5 | บัญชีถูกล็อกชั่วคราว กรุณาลองใหม่หลังเวลา 10:20 น. |
| 10:10:00 | รหัสถูก | บัญชีถูกล็อกชั่วคราว กรุณาลองใหม่หลังเวลา 10:20 น. |
| 10:15:00 | รหัสผิด | บัญชีถูกล็อกชั่วคราว กรุณาลองใหม่หลังเวลา 10:20 น. — ไม่ต่อเวลาล็อก |
| 10:19:59 | รหัสถูก | บัญชีถูกล็อกชั่วคราว กรุณาลองใหม่หลังเวลา 10:20 น. |
| 10:20:00 | รหัสถูก | เข้าสู่ระบบสำเร็จ |

**AS-15 ตัวนับกลับเป็น 0** (BR-06, AU-08)

| ลำดับเหตุการณ์ | ผล |
|---|---|
| ผิด 4 ครั้ง → ถูก 1 ครั้ง → ผิด 4 ครั้ง | ไม่ถูกล็อก |

| ผิด 4 ครั้งเมื่อวาน → ผิด 1 ครั้งวันนี้ | ถูกล็อก — นับติดต่อกันโดยไม่สนช่วงเวลา |

**AS-16 กลับไปหน้าเดิม** (BR-07)

| ค่า `?next=` | หลังเข้าสู่ระบบไปที่ |
|---|---|
| `/courses/SAF-101` | `/courses/SAF-101` |
| `/my-courses?tab=pending` | `/my-courses?tab=pending` |
| (ไม่มี) | `/` |
| `https://evil.example.com` | `/` |
| `//evil.example.com` | `/` |
| `/\evil.example.com` | `/` |
| `courses/SAF-101` (ไม่ขึ้นต้นด้วย `/`) | `/` |

- And ค่า `?next=` เดียวกันใช้กับการสมัครสำเร็จ (AU-09)

**AS-17 login อยู่แล้ว** (AU-10)
- Given ผู้เรียน login อยู่
- When เปิด `/login?next=/my-courses` หรือ `/register`
- Then ถูกพาไป `/my-courses` หรือ `/` ตามลำดับ โดยไม่เห็นฟอร์ม

**AS-18 ออกจากระบบ** (AU-11)
- When กด "ออกจากระบบ" จากเมนูหลัก
- Then ไปหน้า `/` และเมนูหลักแสดง "เข้าสู่ระบบ" และ "สมัครสมาชิก"
- And เปิด `/my-courses` ถูกพาไป `/login?next=/my-courses`

### 5.3 ทั้งสองหน้า

**AS-19 เมนูหลัก**
- Given ยังไม่ login Then เมนูหลักมี "เข้าสู่ระบบ" และ "สมัครสมาชิก"
- Given login แล้ว Then เมนูหลักแสดงชื่อผู้ใช้และ "ออกจากระบบ" ไม่มี "เข้าสู่ระบบ" และ "สมัครสมาชิก"

**AS-20 การเข้าถึง (Accessibility)**
- Then ทุกช่องมี label ที่อ่านได้ด้วยโปรแกรมอ่านหน้าจอ ข้อความผิดพลาดผูกกับช่องที่ผิด
- And ตรวจด้วย axe แล้วไม่มี violation ระดับ `serious` หรือ `critical`

**AS-21 มือถือ**
- Given หน้าจอกว้าง 375 px
- Then ทั้งสองหน้าไม่มี scroll แนวนอน และกรอกฟอร์มได้ครบโดยไม่ต้องซูม

## 6. Decisions

| ประเด็น | การตัดสินใจ | เหตุผล |
|---|---|---|
| ข้อความเมื่อบัญชีถูกล็อก | บอกว่าล็อกและเวลาที่ลองใหม่ได้ | หน้าสมัครบอกอยู่แล้วว่าอีเมลใดมีในระบบ (BR-02) การซ่อนสถานะล็อกจึงไม่ได้ป้องกันเพิ่ม แต่ทำให้ผู้ใช้สับสนว่าทำไมรหัสถูกแล้วเข้าไม่ได้ |
| ครั้งที่ผิดครั้งที่ 5 แสดงอะไร | แสดงข้อความล็อกทันที | ผู้ใช้รู้ตั้งแต่ครั้งนั้นว่าต้องรอ ไม่ต้องลองครั้งที่ 6 แล้วจึงรู้ |
| ช่วงเวลาของ "ติดต่อกัน" | ไม่มีกรอบเวลา รีเซ็ตเมื่อ login สำเร็จหรือพ้นล็อกเท่านั้น | ตรงตาม BR-06 และทดสอบได้ชัดเจน |
| อีเมลที่ไม่มีในระบบ | ไม่นับครั้งและไม่ล็อก | ไม่มีบัญชีให้ล็อก |
| วิธีนับตัวอักษรชื่อภาษาไทย | นับทุกตัวรวมสระบน/ล่างและวรรณยุกต์ | คาดเดาได้และตรงกับที่ผู้ใช้เห็นตัวนับในช่อง ความต่างกับการนับแบบ "ช่องแสดงผล" มีผลแค่ชื่อที่ใกล้ 2 หรือ 100 ตัว |
| โดเมนอีเมลพนักงาน | ต้องเป็น `@pea.co.th` ตรงตัว ไม่รับ subdomain | ยังไม่มีข้อมูลว่า กฟภ. ใช้ subdomain อีเมล |
| หลังสมัครสำเร็จ | เข้าสู่ระบบให้อัตโนมัติ | ผู้สมัครส่วนใหญ่มาจากปุ่ม "เข้าสู่ระบบเพื่อลงทะเบียน" ของหลักสูตร (R3) ควรกลับไปลงทะเบียนต่อได้ทันที |
| รหัสพนักงานที่ขึ้นต้นด้วย 0 | เก็บเป็นข้อความ 6 หลัก | รหัสเป็นตัวระบุ ไม่ใช่ตัวเลขสำหรับคำนวณ |
| การออกจากระบบ | อยู่ในขอบเขต | requirement ไม่ได้ระบุ แต่ระบบที่ login ได้ต้องออกได้ โดยเฉพาะเครื่องใช้ร่วมในสำนักงาน |
